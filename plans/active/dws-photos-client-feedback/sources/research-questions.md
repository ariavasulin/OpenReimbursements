# Research Questions

All paths are relative to `dws-app/` unless stated. `Docs/` (Architecture, Database, Employee-Features, Admin-Features, photos-runbook) is the codebase map; `plans/active/dws-hosted-mcp/`, `plans/active/photo-albums/`, and `plans/active/photo-folders/` record earlier photo decisions. Describe what exists today, with file:line references. Where the code and the docs disagree, report both.

1. **Photo data model.** Using `supabase/migrations/*photo*`, `00000000000003_photos_schema.sql`, and `src/lib/photos/types.ts`, document the current columns, constraints, indexes, and relationships of `jobs`, `photos`, `albums`, `album_photos`, tags, `photo_content_claims`, and `photo_share_links`. Cover specifically: whether a photo must belong to a job; how a job's number and name are stored and whether they are unique or editable; what uploader, upload-time, taken-at, file-name (`display_name`, original name, storage path), and MIME/file-type fields exist on a photo; and every soft-delete / purge column (`deleted_at`, `purged_at`, and similar) on each table.

2. **Where jobs (projects) come from.** Trace every path that creates or renames a `jobs` row: the `/api/photo-jobs` routes, `new-job-form.tsx`, `rename-sheet.tsx`, `job-combobox.tsx`, the `/migrate` folder import, the MCP tools under `src/app/mcp`, seeds, and scripts. Is there any existing import, sync, or reference to a system outside this app (another database, spreadsheet, CSV, or API) as a source of job numbers or names? How are jobs searched and listed in pickers?

3. **Roles and permission to change photos.** How is a user's role stored and checked (`user_profiles.role`, `is_admin()`, `src/lib/photos/server/authority.ts`, RLS policies in the photo migrations, `src/middleware.ts`)? For each photo operation — upload, edit metadata, rename, move to another project, add to album, trash, restore, delete forever, empty/purge, delete or restore a project or album, create share links, import folders — which roles or users are allowed today, and is the check made in SQL, in the route handler, or both? Which of these rules changed in `plans/active/photo-albums/plan.md` (for example its Decision 7) and the latest migrations `20260923120000_photo_manage_and_purge.sql` and `20260923180000_photo_manage_followups.sql`? How are admin users created or promoted today (UI under `src/app/users`, SQL, runbook)?

4. **Trash and permanent deletion, end to end.** Trace a photo, a project, and an album from trash, through `src/app/photos/trash/page.tsx`, `/api/photos/trash`, `/api/photos/trash/purge`, `src/lib/photos/server/purge.ts`, and the repair sweep (`/api/photos/repair`, `vercel.json` cron). What happens to Storage objects (originals, derivatives, sidecars), `photo_content_claims`, album memberships, and share links? Does automatic 30-day expiry exist, and does any "remove everything in trash" or bulk-purge operation exist? What runbook procedures in `Docs/photos-runbook.md` cover wiping or resetting photo data, and what test or seed data does production currently hold (read-only counts if reachable with the logged-in Supabase CLI)?

5. **Tags.** How are tags stored (column vs. table), created, normalized, and listed (`/api/photo-tags`, `/api/photos/tags`, `get_photo_tags` RPC, `src/lib/photos/tags*`, `tag-input.tsx`, `tag-dropdown.tsx`, `filter-options`, `migrate/folder-tags.tsx`)? Is the tag vocabulary global, per user, or per project today, how is its list ordered, and how does the folder import create tags?

6. **Selection and bulk operations.** Document `use-photo-selection.ts`, `src/lib/photos/selection.ts`, `batch.ts`, `selection-bar.tsx`, `collection-select-bar.tsx`, `set-project-sheet.tsx`, `edit-photo-sheet.tsx`, `photo-meta-fields.tsx`, and the `/api/photo-actions/batches` routes. On which surfaces (project page, date/tag/project groups, projects list, albums list, album page, search, trash) can a user select many items, what can "select a whole group" do, and which bulk edits (tags, project, album, date, rename, trash, restore, delete forever, download) exist per surface? Is there any download or zip export of photos anywhere, including share links?

7. **Grouping, sorting, and album order.** In `src/lib/photos/group.ts`, `group-by-toggle.tsx`, `sections-rail.tsx`, `section-nav.tsx`, `photo-browser.tsx`, and the server read paths (`src/lib/photos/server/reads.ts`, `collectionPagination.ts`, aggregation RPCs), what group-by modes exist on each surface, what field and direction each group and each photo inside a group sorts by, and can a user change sort direction? How does pagination interact with grouping? How are photos inside an album ordered — does `album_photos` carry a position column or order by date?

8. **Upload identity and duplicates.** Trace an upload through `hash.worker.ts`/`hash-core.ts`, `/api/photos/exists`, `/api/photos/dedupe`, `upload-*.ts`, `src/lib/photos/server/uploads.ts`, and `photo_content_claims`. What makes two files "the same" today (byte hash, file name, EXIF, perceptual similarity)? What does the user see when an exact duplicate is uploaded, from the camera, the upload sheet, and `/migrate`? What file types and extensions are accepted (JPEG, HEIC, PNG, RAW formats such as CR2/NEF/ARW/DNG, video), and how are non-browser formats displayed (derivatives in `derivatives.ts`)?

9. **Capture metadata and file naming.** In `src/lib/photos/exif.ts` and its callers, which EXIF fields are read (DateTimeOriginal, sub-seconds, time-zone offset, camera), for which formats, and which EXIF library is used (see `package.json`) and what formats does that library support? When no EXIF date exists, what is stored? How are the Storage object key and the user-visible file name decided at upload, at rename, and at download/share time?

10. **Viewing a photo.** Describe `photo-lightbox.tsx`, `full-screen-sheet.tsx`, `photo-info.tsx`, `photo-grid.tsx`, `shared-gallery.tsx`, and `use-photo-deep-link.ts`: layout on phone vs. desktop widths, how image size is chosen (derivative sizes, `object-fit`), which controls and chrome are shown and whether any can be hidden, gestures and keyboard navigation, zoom, video playback, and any existing auto-advance or timed playback. What lightbox or gesture libraries are in use?

11. **Search.** Document `src/app/photos/search/page.tsx`, `search-box.tsx`, `filter-bar.tsx`, `job-filter.ts`, `filter-options`, and the server query behind them: which fields are searchable (text, project, tag, uploader, date range, file type, album), how multiple filters combine (AND/OR), whether filter state lives in the URL, and what actions are available on a result set (select, add to album, download, share).

12. **Albums.** How are albums created and populated (`new-album-sheet.tsx`, `album-field.tsx`, `/api/photo-albums`, migrate `album-choice.tsx`), from which surfaces can photos be added to an existing or new album, and how are album pages rendered and paginated?

13. **Photos UI design system.** What component library and primitives do the photo pages use (shadcn/ui in `src/components/ui`, custom components)? Document the colors with hex codes (for example `#2e2e2e`, `#4e4e4e`, `#b4b4b4`, `#2680FC`), typography, spacing, radii, borders, and shadows used by the photo shell, plus the phone vs. desktop layout system (`page-layout.ts`, `phone-header.tsx`, `top-bar.tsx`, `sections-rail.tsx`). Is there a theme system or only hard-coded values?

14. **Test and release surfaces.** What unit, integration (`integration/`, `vitest.integration.config.ts`), and browser (`tests/browser`, Playwright) tests cover the areas above, how are they run, and what feature flags or release state (`photo_release_state`, env flags such as `PHOTOS_TRANSCODE`, sharing enabled) gate photo features in production?
